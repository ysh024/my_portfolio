Exactly. Ab development start karne se pehle humein **portfolio ka complete planning package** ready karna chahiye, taaki coding ke beech mein structure baar-baar change na karna pade.

Main is project ko **Next.js + TypeScript + Framer Motion + static/data-driven architecture** par define kar raha hoon. Backend/database abhi intentionally nahi rakhenge.

# 1. Portfolio Project — Master Definition

**Project name:** Personal Developer Portfolio
**Positioning:** Independent Web Developer / AI-Assisted Web Developer
**Primary goal:** Skills, projects, services and development approach ko professional way mein present karna aur potential clients/employers ko contact karne ka clear path dena.

**Target audience:**

* Small/local businesses
* Startups
* Creators
* Individuals needing websites
* Businesses needing integrations
* Potential collaborators
* People evaluating your technical skills

**Primary CTA:** Contact / Let's Work Together
**Secondary CTA:** View Projects

# 18. Animation Rules

Framer Motion should be used, but **not everywhere**.

Use:

* Page entrance
* Scroll reveal
* Staggered cards
* Hover interactions
* Image transitions
* Navigation transitions
* Project filtering
* CTA interactions

Avoid:

* Constant floating animations
* Excessive parallax
* Huge 3D animations
* Slow page transitions
* Animations that hurt mobile performance

Goal:

**smooth, premium, not distracting.**

## One thing I would change from our earlier plan

I **wouldn't make "Skills" a completely separate top-level page unless the content becomes substantial**.

For a personal developer portfolio, the strongest navigation can be:

```text
Home
About
Projects
Services
Experiments
Contact
```

And **Skills/Technologies** can be a strong section on Home + About.

That keeps the navigation clean while still showing everything.

### Final navigation

```text
YASH
────────────────────────────────
Home   About   Projects   Services
Experiments                         Contact
```

This is the structure I'd freeze before development.

**Next, the most useful thing to prepare is the actual content package**—exact Home copy, About copy, Services copy, project-card fields, project case-study template, Experiments template, CTA text, SEO titles/descriptions, and the `projects.ts / services.ts / skills.ts` data structure. That becomes the actual content source for the Next.js build rather than leaving the AI/developer to invent content while coding.
